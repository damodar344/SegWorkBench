2. FIX: Real Train/Validation Split in Main app.py
--------------------------------------------------------------------------------

PROBLEM:
The TrainingTab in Main app.py used the ENTIRE dataset for training and had
no validation set. It trained for N epochs and blindly saved the model from the
last epoch, even if the model had started overfitting earlier. The loss plot
only showed training loss, giving users no signal about generalization.

SOLUTION:
Rewrote `_train_loop()` in Main app.py to perform an 80/20 train/validation
split using PyTorch's `random_split`.

KEY CHANGES IN Main app.py:
  a) Imports
     - Added `random_split` to the `torch.utils.data` import line.

  b) Plot initialization (TrainingTab.__init__)
     - Added a second plot line: `self.line_val_loss`
     - Renamed legend labels from "Loss" -> "Train Loss" / "Val Loss"
     - Added `self.val_losses = []` list to store validation loss history.

  c) _train_loop() logic
     - Splits dataset with 20% held out for validation.
     - Falls back gracefully for tiny datasets (ensures at least 1 validation
       sample and errors out if < 2 total samples).
     - Creates separate `train_loader` and `val_loader`.
     - Tracks `best_val_loss` and `best_model_state` across epochs.
     - Runs a validation pass in `eval()` mode with `torch.no_grad()` after
       each training epoch.
     - Updates the GUI status bar with BOTH losses each epoch.
     - Updates the loss plot with BOTH curves each epoch.
     - At the end of training, restores and saves the model with the LOWEST
       validation loss (filename: `*_unet_best_val.pth`), NOT just the final
       epoch model.

BEFORE:
  Epoch 5/20 | Loss: 0.1234
  -> Saves final epoch weights regardless of quality.

AFTER:
  Epoch 5/20 | Train Loss: 0.1234 | Val Loss: 0.1456
  -> Saves the model from the epoch with the best validation loss.

--------------------------------------------------------------------------------
1. OVERVIEW: Tkinter → PySide6 Migration
--------------------------------------------------------------------------------

PROBLEM:
The entire application lived in a single ~1,200-line tkinter script
(Main app.py). tkinter is outdated, hard to theme, and lacks high-performance
interactive widgets (e.g., zoomable image canvases). The monolithic file
mixed GUI code, training loops, inference logic, GMM analysis, and mask editing
geometry, making maintenance difficult.

SOLUTION:
Replaced the tkinter GUI with a modern PySide6 (Qt for Python) application.
Split the monolith into a clean package structure:

  • segworkbench/engine/     — Training & inference back-ends
  • segworkbench/utils/      — Image processing helpers
  • segworkbench/analysis/   — GMM / threshold algorithms
  • segworkbench/editor/     — Mask editing geometry & undo stack
  • segworkbench/gui/        — Qt tabs, widgets, stylesheets
  • segworkbench/configs/    — Model + application settings

The old script was renamed to "Main app_tkinter.py" for reference.
New entry points are:

    python main.py
    python -m segworkbench

Date: 2024-11-05
Tasks: Category 3 (Architecture) + Category 4 (Performance/Robustness) + Category 5 (ML/Training) + Category 6 (Inference/I/O) + Hang Fix

--------------------------------------------------------------------------------
1. CODE ARCHITECTURE (Category 3)
--------------------------------------------------------------------------------

A) Deduplicated entry points
   main.py is now a thin wrapper:
       from segworkbench.__main__ import main
   Previously it duplicated the entire QApplication bootstrap.

B) ModelConfig / CheckpointManager wired into Trainer
   Trainer.train() accepts an optional config: ModelConfig.
   When provided, epochs / batch_size / lr / image_size / patience / min_delta
   are read from the config, and CheckpointManager.save() is called on every
   new best-validation epoch.

C) QThread workers replaced threading.Thread
   segworkbench/gui/workers.py (NEW)
       TrainingWorker(QThread)  — runs Trainer.train()
       InferenceWorker(QThread) — runs Inferencer.run()
   Signals:
       epoch_finished.emit(dict)   — {epoch, total, train_loss, val_loss, dice, iou}
       training_finished.emit(dict, bool)
       progress.emit(int, int, str)
   Tabs connect directly to pyqtSignal instead of using safe_call() marshalling.

D) Structured logging
   Added logging.getLogger(__name__) to:
       segworkbench/engine/trainer.py
       segworkbench/engine/inferencer.py
   Key events logged at INFO:
       training start/finish, epoch summary, early stop, inference start/finish.

--------------------------------------------------------------------------------
2. PERFORMANCE & ROBUSTNESS (Category 4)
--------------------------------------------------------------------------------

A) Fixed QImage buffer lifetime crash
   mask_editor_tab.py — both _render_overlay_pixmap and _pil_to_pixmap now call
   .copy() after constructing QImage(...). This ensures Qt owns the pixel buffer
   and prevents segfaults when the NumPy array is garbage-collected.

B) Enabled weights_only=True in torch.load
   configs/model_config.py  — CheckpointManager.load() and load_checkpoint()
   engine/inferencer.py     — Inferencer.run()
   Removes security warnings with untrusted checkpoints.

C) Fixed batch-size bug in SegDataset
   Changed T.Resize(256) → T.Resize((256, 256)) for both images and masks.
   T.Resize(int) resizes the shorter edge, yielding variable dimensions that
   break batch collation. T.Resize((int, int)) guarantees a fixed square output.

D) Exposed num_workers
   Trainer.train() accepts num_workers kwarg.
   TrainingTab added a Workers spin-box (0–16, default 0).
   Passed through to both train_loader and val_loader.

E) CPU thread capping (hang fix)
   When Trainer detects a CPU-only device, _limit_cpu_threads() caps
   torch.set_num_threads(4). This prevents OpenMP from spawning one thread
   per core and starving the Qt event loop, which previously caused the
   entire system to hang on multi-core CPUs.

--------------------------------------------------------------------------------
3. MACHINE LEARNING / TRAINING (Category 5)
--------------------------------------------------------------------------------

A) Data augmentation
   SegDataset._random_affine applies identical transforms to image + mask:
       - Horizontal flip (p = 0.5)
       - Vertical flip   (p = 0.5)
       - Rotation        (uniform ±15°)
   Enabled only for training data; validation subset uses augment=False.

B) Segmentation metrics
   Added _dice_score() and _iou_score() helpers.
   Validation loop accumulates per-batch Dice and IoU and reports epoch averages.
   TrainingTab now shows a second live matplotlib plot (Dice + IoU) side-by-side
   with the loss plot.

C) LR scheduler
   torch.optim.lr_scheduler.ReduceLROnPlateau
       mode="min", factor=0.5, patience=max(1, config.patience // 2)
   Steps each epoch based on validation loss.

D) Early stopping
   Reads patience and min_delta from ModelConfig.
   Counter increments when validation loss does not improve by min_delta.
   Training halts when counter reaches patience.

E) MPS support (Apple Silicon GPU)
   _auto_device() now checks torch.backends.mps.is_available() between CUDA
   and CPU fallback. Both Trainer and Inferencer use this helper.

--------------------------------------------------------------------------------
4. INFERENCE & I/O (Category 6)
--------------------------------------------------------------------------------

A) Original resolution restoration
   Inferencer no longer saves 256×256 masks.
   After model inference at the configured square size, the probability map is
   upsampled back to the original (width, height) via F.interpolate() with
   bilinear mode before thresholding.

B) Configurable threshold
   Added threshold kwarg to Inferencer.run() (default 0.5).
   InferenceTab exposes a QDoubleSpinBox (0.00–1.00, step 0.05).

C) 16-bit / grayscale support
   Added preserve_depth kwarg to Inferencer.run().
   InferenceTab exposes a QCheckBox "Preserve 16-bit depth".
   When enabled, L / I / I;16 / F mode images are normalized directly without
   forcing .convert("RGB"), preserving full dynamic range for scientific TIFFs.

D) Configurable image_size
   Inferencer.run() accepts image_size kwarg.
   InferenceTab exposes a QSpinBox (64–2048, default 256).
   Controls the model input crop; output is still restored to original resolution.
